## 1. 검증 게이트

아래 순서로 실행한다. 하나라도 실패하면 **거기서 멈추고** 원인을 보고한다.
실패를 우회하거나 테스트를 지워서 통과시키지 않는다.

```
pnpm lint → pnpm typecheck → pnpm test:unit → pnpm build
```

파서나 응답 처리를 건드렸다면, `fixtures/raw/`의 실제 응답 픽스처로 검증하는 테스트가
포함되어 있는지 확인한다. 없으면 추가한 뒤 게이트를 다시 돌린다.

## 2. 문서 갱신

### `PROGRESS.md`

- 현재 단계와 단계별 상태 표
- **결정 기록** — 이번에 내린 판단과 그 근거를 한 줄씩
- **해소된 질문** — 🔶를 ✅로 옮긴다.
  🚨 실제 응답 원문이나 실행 결과를 근거로 제시할 수 있을 때만 옮긴다.
  근거가 추론이면 어디까지가 실측이고 어디부터가 추론인지 밝힌다.
- **미해결 질문** — 새로 생긴 🔶를 추가한다
- **확인된 함정 🚨** — 이번에 실제로 겪은 것을 추가한다
- **다음 액션**

### `ROADMAP.md`

완료한 항목의 체크박스를 채운다. DoD를 충족하지 못한 항목은 **체크하지 않는다.**
부분 완료면 무엇이 남았는지 그 자리에 적는다.

### `.claude/skills/typhoon-map/SKILL.md`

규약이 실제 응답과 어긋난 것이 확인되면 고친다. 🔶를 ✅로 바꿀 때는 확정된 값을 함께 적는다.
🚨 스킬 문서를 고쳤다면 그 사실을 보고에 반드시 포함한다.

### `claude_results.md`

**덮어쓰기**로 새로 쓴다. 담을 것.

- 결론 — 무엇이 끝났고 무엇이 안 끝났는지
- 판정·결정과 그 근거. 응답 원문이나 실행 출력을 인용한다
- 만든 것
- 도중에 잡은 문제
- 남은 🔶
- 검증 게이트 결과
- 짚어둘 것과 다음 단계

## 3. 커밋과 푸시

- 🚨 `git add -A` 금지. 변경 파일을 **개별로** add 한다.
  add 전에 `git status --short`로 의도한 파일만 올라가는지 확인한다.
- `.dev.vars`가 스테이징되지 않았는지 확인한다.
- 픽스처를 새로 수집했다면, 스테이징된 블롭이 원본 바이트와 같은지 확인한다.
  🚨 `core.autocrlf` 때문에 커밋 시점에 줄바꿈이 바뀔 수 있다.
- 커밋 메시지는 **무엇을 왜 바꿨는지**를 적는다. 특히 가정이 틀린 것으로 드러났다면
  그 사실과 근거를 남긴다.
- `main`에 직접 푸시한다. 별도 지시가 없으면 브랜치나 PR을 만들지 않는다.
- 푸시 후 원격 CI 결과를 확인한다. 해당 커밋 SHA의 워크플로가 끝날 때까지 기다린다.

## 4. 보고

- 게이트 결과 (lint / typecheck / test:unit 개수 / build / 원격 CI)
- 커밋 해시와 무엇이 들어갔는지
- **끝내지 못한 것** — DoD 미충족 항목, 확인하지 못한 것, 사용자가 직접 해야 하는 것.
  🚨 이걸 빠뜨리지 않는다. 완료로 보고하려고 범위를 줄이지 않는다.

## 지킬 것

- 요청받지 않은 리팩터링이나 의존성 추가를 이 단계에서 끼워 넣지 않는다.
- 게이트를 통과시키려고 테스트를 약화시키지 않는다.
- 확인하지 못한 것을 확인한 것처럼 쓰지 않는다.
